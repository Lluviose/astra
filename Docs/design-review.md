# Astra 逐页设计审查

本轮由用户反馈推动：完成 React Native 架构不等于完成重新设计。设计审查以实际页面的比例、信息层级、阅读顺序和操作体验为依据。

## 本轮修改

| 页面 | 原先的问题 | 新的设计处理 |
| --- | --- | --- |
| 后宫 | 标题和大图占满首屏，档案信息退到图片下方 | 竖幅照片与档案侧栏组合；人物、城市、标签和相处次数形成分层；最近记录与其他人物紧随其后 |
| 战绩 | 搜索、两排筛选和跟进区域挤压记录 | 次要筛选按需展开；日期、月份和事件形成连续时间线；跟进折叠为一行入口 |
| 殿堂 | 统计卡、柱图和徽章并列，重点分散 | 累计数与六个月趋势整合；相处构成使用真实比例；里程碑改为有状态的条目 |
| 人物档案 | 重复首页的大图结构，内容入口较深 | 横幅封面、紧凑统计、主操作与下方分区；首屏能够开始阅读记录 |
| 人物画像 | 全部信息以相似字号和平行进度条呈现 | 个人描述与六维雷达分开；综合评分有独立位置，维度数值可直接读取 |
| 私藏与照片 | 相册与普通列表缺少区别，单张照片仍出现空的翻阅操作感 | 相册按照片数量调整版面；照片按实际可用区域完整显示；单张隐藏翻页按钮，多张提供缩略图；双击／双指缩放，拖动有边界 |
| 人物名册 | 普通头像列表，档案区分度不足 | 双列档案与独立照片比例；姓名、城市、亲密次数及评分分层 |
| 偏爱排行 | 每行完全相同，首位与后续缺少层级 | 首位人物单独编排，封面随内容伸展，窄屏姓名与评分不再超出照片高度；其余用紧凑、有序的比较行 |
| 城市足迹 | 地图和列表只是纵向堆放 | 地图作为视觉中心，城市条目显示次数与最近相处日期 |
| 新增／编辑记录 | 长表单缺少填写顺序，保存与错误提示距离太远 | 人物、事件、补充细节分组；保存固定在底部，错误就在按钮上方；键盘避让与底部安全区域配合；窄屏选项可换行 |
| 新增／编辑人物 | 封面与输入分离，评分横向数字过密 | 封面与档案摘要合成一个入口；基本资料与印象分区；评分逐项增减；共用底部保存区，返回时确认放弃未保存修改 |
| 设置 | 寄语输入先占首屏，隐私控制靠后 | 隐私与体验优先；寄语、档案管理和版本信息各自分区 |
| 空状态／确认框 | 大色块图标和居中按钮模板化 | 空状态使用纸页式图形；删除确认集中在底部面板，保留清晰的后果说明与取消入口 |
| 共有细节 | 工具栏随长内容消失；小头像的首字被裁切；辅助文字偏小 | 工具栏固定；无照片占位字按实际容器缩放；辅助文字由 11 调整为 12pt；统一间距与触摸范围 |

## iPhone 审查范围

按用户最新要求，继续聚焦手机端 iOS，不以云端 macOS 验证作为本轮推进条件。这里的 macOS 运行器用于运行 iPhone 模拟器，不代表产品改为 macOS 应用。三个云端工作流均改为手动触发；React Native 工作流中的模拟器构建还需明确勾选，默认关闭。后续提交和 PR 更新不再自动启动这些任务。

本轮按 320、375、390、430pt 手机宽度检查代码中的空间约束、照片比例、触摸范围和阅读层级。此项为静态审查，不等于在这些设备上实际运行。

## 后续原生验收方式

原生 UI 审查通过应用控件进入每个页面，保存首屏、长内容与关键状态截图。审查时检查：

- 第一眼是否能识别页面主题与主操作。
- 相邻信息是否有明确字号、间距或位置层级。
- 照片是否尊重比例，正文是否清晰、不过度截断。
- 筛选、空内容、隐藏内容和表单展开后的布局是否成立。
- 长页面中的返回、编辑和保存是否容易找到。

当前进度：页面代码已重做，并完成静态布局审查；32 个 TypeScript/TSX 文件通过离线 TypeScript 与 Babel 语法解析，现有 10 项业务测试通过。语法解析不等于完整类型检查；本轮未执行完整类型检查、iOS 构建或新版原生截图验收。

静态审查已修正：收藏侧栏高度超出照片的问题、320pt 名册两列因间距换行的问题、雷达标签随图表缩小而难以阅读的问题，以及趋势数据点与月份标签未对齐的问题。

此前云端运行在分配运行器之前失败。用户提供的 GitHub 注释显示账户付款或支出额度限制，任务未启动；这不构成代码测试失败，也没有产生新版截图。用户已明确要求不再为此停留在 macOS 验证上，因此本轮继续完成手机界面工作，不重跑云端任务，也不修改账户计费设置。需要原生验收时，可在已有的本地开发环境中执行 `mobile/native-tests/ModernUITests.swift` 的逐页流程。
