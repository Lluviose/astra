# Astra 现代版设计与架构

用户要求使用 React Native 重设计，开发阶段不需要备份或历史迁移。本版采用 Expo / TypeScript / SQLite，独立入口为 `mobile/`。

## 为什么采用这套架构

React Native 让布局和交互可以用同一套组件迭代，Expo 管理原生工程生成、照片、数据库与设备认证等接入。选择它的价值是降低设计迭代与原生集成的维护成本；视觉品质仍取决于排版、内容密度、留白、照片和交互细节。

| 层 | 实现 | 用途 |
| --- | --- | --- |
| 页面与导航 | React Native、Expo Router | 三个主标签、原生堆栈、模态编辑流程 |
| 设计系统 | 统一颜色、字体、间距和基础组件 | 一次调整可在页面间一致生效 |
| 交互动画 | Reanimated、Gesture Handler | 照片缩放、拖动与手势协作 |
| 状态 | Zustand | 已加载档案、隐藏状态、提示及写入队列 |
| 业务逻辑 | TypeScript 纯函数 | 输入校验、组合筛选和统计，可独立测试 |
| 持久化 | Expo SQLite、应用内照片文件 | 写入事务成功后再更新界面 |
| 原生能力 | Expo 模块、react-native-maps | 系统照片选择、设备认证、后台保护与城市地图 |

网页运行入口用于快速检查共享页面；SQLite、系统认证和原生地图仍由 iOS 版本承担。生产版本默认空白，示例构建使用独立数据库。

## 视觉方向

中性纸色背景、石墨色文字和少量蓝色交互提示。核心改变是页面编排：后宫将竖幅照片与档案侧栏结合；战绩以月份、日期和事件组织阅读，按需展开筛选；殿堂把累计数据、六个月趋势和相处构成整合起来。人物页使用横幅封面和分区内容，与首页形成区别。

辅助页面分别采用双列名册、首位突出的排行、以地图为中心的足迹、分组表单与隐私优先的设置。共用工具栏固定在顶部。逐页变更及验收状态见 [设计审查](design-review.md)。

## 交互与结构

三个主标签为后宫、战绩、殿堂。底部新增按钮直接进入记录；人物不足时可当场建档。详情导航使用原生 Stack，记录与人物编辑使用模态流程。页面通过 TypeScript 领域函数校验变更，再通过串行写入队列存入 SQLite 事务，成功后更新状态。

设计变量和基本组件统一定义在 `src/design/ui.tsx`。宽屏使用双栏，手机保持单列；操作目标至少 44pt。页面允许滚动，照片有无、空记录、长备注和隐藏状态均有专门呈现。

## 本轮交付边界

交付可运行的全新版本和主要功能闭环。旧版 SwiftUI 工程留在原位置作参考；本轮不迁移其数据库、备份、全量评级或成就规则。新版本使用独立 bundle identifier，正式切换生产入口属于后续发布工作。

正常构建从空白状态启动；示例构建采用单独数据库并标注示例。示例照片和人物全部虚构。原生地图、认证、照片选择与后台保护需要在 iOS 运行环境验收，网页预览不替代这些能力。
