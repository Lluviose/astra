# 记录模块产品设计

## 定位

记录模块服务于成年男性管理自愿的非固定亲密关系：猎艳、约炮、过夜、留照片、看自己约成几次。核心价值是事后还能翻到「和谁、做了什么、爽不爽、有没有戴套、照片在哪」，并完成必要的沟通或健康跟进。

## 用户真正要完成的任务

| 优先级 | 用户任务 | 产品回应 |
| --- | --- | --- |
| P0 | 很快记住“和谁、何时、是什么类型” | 对象、时间、地点和类型先出现，其余均可跳过或稍后补 |
| P0 | 记清实际行为与屏障使用 | 行为按临床上有意义的方式拆分；屏障区分全程 / 部分 / 未用，并与 PrEP、避孕等措施分开 |
| P0 | 不遗漏自己决定要处理的事情 | 消息确认、检测、暴露咨询、妊娠相关、身体状况可组成一条待跟进任务 |
| P1 | 回看边界是否舒服、当时状态是否影响判断 | 只记录用户本人的观察，不替双方作“已同意”认证 |
| P1 | 分清“身体舒服”和“情绪舒服” | 两个可选维度，未填就是未记录，不用默认分污染回顾 |
| P1 | 决定是否还想再见 | 想再见 / 看情况 / 不再约 / 未决定，帮助后续行动而非评价对方 |
| P0 | 避免隐私暴露 | 代号、默认遮罩、本地保存；照片不进系统相册、不上传；待跟进仅在用户主动创建后出现 |
| P1 | 留下这次的照片或她的头像 | 头像和艳照只存在 App 沙盒，不进系统相册，代号打码时糊掉 |

## 面向男性用户的产品假设

以下是需要后续访谈验证的设计假设，不当作“男性都如此”的事实：

1. 刚结束见面时，用户更愿意点选少量事实，而不是写长篇日记。因此基础记录可以立即保存，敏感细节渐进展开。
2. 健康提示如果带有道德评判或直接把对象标成“高风险”，容易造成回避和错误安全感。因此只围绕实际行为、屏障方式和用户主动提出的担忧。
3. “表现评分”会把注意力推向时长、勃起或次数，却遗漏身体不适、紧张、酒精和事后情绪。记录改为身体感受与情绪感受，并允许完全不评分。
4. 异性恋假设会让男男性行为、双性恋用户或不同身体结构的伴侣无法准确记录。因此行为字段使用“主动 / 接受”和具体部位，不绑定身份标签。
5. 一次亲密行为后的核心价值往往发生在未来：是否联系、何时检测、是否咨询。因此待跟进必须能从单条记录进入首页，而不是埋在备注里。

## 准炮友 / 聊天阶段（男性记录女性）

这个阶段不是“攻略漏斗”，而是双方尚未发生线下亲密行为时的信息确认期。男性用户需要减少误读、记住她明确表达的范围，并决定自己的下一步。

| 容易出现的误区 | 记录模块的替代设计 |
| --- | --- |
| 用回复速度、字数或表情猜测她是否愿意 | 只记录她是否对露骨文字 / 图片 / 视频作出明确回应 |
| 把一次调情当作以后所有内容和线下行为的许可 | 提醒同意是具体、持续且可撤回的；不同媒介与行为分别确认 |
| 只记“聊得很骚”，忘了实际谈过什么 | 用关系期待、尺度 / 节奏、偏好、边界、隐私、防护 / 检测、避孕责任、饮酒 / 物质边界和见面安排分类 |
| 私密图片默认可保存、截屏或转发 | 单独记录不截屏、不转发、不保存、不露脸等明确约定；App 把用户主动留下的照片存在沙盒，不进系统相册、不上传 |
| 男性用户忽略诈骗、账号盗用或性勒索风险 | 只记录转账要求、可疑链接、被催促发私密内容、传播威胁等可观察事实，并提供暂停 / 举报 / 求助后续 |
| 为了推进而持续追问 | 进展可以是放慢或停止；她明确拒绝时显示停止升级提示 |
| 把健康沟通拖到临见面或性行为发生前 | 在暧昧记录里就能标记已经聊过防护 / 检测，并把未完成事项放入跟进 |

记录页为这一阶段提供“聊天”筛选；对象详情提供直接的“聊天”入口。一次记录包含：当前进展、露骨内容回应、明确聊过的话题、线上隐私约定、用户自己的情绪、是否继续，以及发消息或安排见面的下一步。筛选到“聊天”后，顶部只显示聊天记录、本月记录、明确回应填写数和待跟进，不展示“转化率”或成功率。

相处状态在暧昧中和炮友之间有「准炮友」：已经明确会约、但还没真正约成。炮友 / 固定炮友表示已经在约。

## 交互结构

```text
基础（默认可直接保存）
├─ 对象 / 时间 / 地点 / 类型
├─ 这次的照片（可选，最多 8 张）
└─ 亲密类型时继续
   ├─ 发生了什么（事实）
   ├─ 边界与当时状态（按需展开）
   ├─ 防护与健康（屏障状态始终可见，细节展开）
   ├─ 我的感受（可跳过）
   └─ 后续处理（用户主动创建）
```

记录页提供“全部 / 聊天 / 约成 / 跟进”四个入口。首页只提升尚未完成的跟进，不自动把“部分使用或未用屏障”转换成医疗结论或系统提醒。

## 关键文案原则

- 用“未用安全套 / 屏障”，不用笼统的“危险行为”。
- 用“边界感受”，不用用户无法替对方证明的“已获得同意”。
- 用“身体感受 / 情绪感受”，不用“床上表现”。
- 用对方的代号，语气可以直白，但不做对外排行。
- 健康字段陈述用途差异，不计算风险分；具体建议交给专业机构。

## 明确不做

- 不做对外战绩榜、把人按次数排序或分享到别处的成就墙。本地徽章可以有，只给用户自己看。
- 不给对象打“干净 / 不干净”“高危 / 低危”等标签。
- 不用伴侣外貌、身份、职业或自述推断 STI 风险。
- 不自动推断避孕需求，也不默认对象具备受孕可能。
- 不把 PrEP、其他避孕和安全套混成一个“已防护”开关。
- 不默认推送敏感通知；用户没有创建后续任务时不提醒。
- 不把照片写入系统相册、不上传、不加入 iCloud 备份。

## 健康与伦理依据

- [WHO：Sexual health](https://www.who.int/health-topics/sexual-health) 将性健康定义为身体、情绪、心理和社会层面的福祉，并强调尊重、安全与免于强迫。
- [CDC：Getting Tested for STIs](https://www.cdc.gov/sti/testing/index.html) 指出检测项目与频率取决于性史、实际行为、症状等，口交或肛交也可能涉及相应部位检测。
- [CDC：Conversation Tips](https://www.cdc.gov/sti-awareness/pbyt/conversation.html) 建议在发生性行为之前，与伴侣开放、诚实且不带评判地讨论性健康。
- [CDC：Condom Use](https://www.cdc.gov/condom-use/index.html) 说明正确、持续使用安全套能够降低风险，但不能把风险降为零。
- [CDC：Preventing HIV with PEP](https://www.cdc.gov/hiv/prevention/pep.html) 说明 PEP 属于暴露后的紧急措施，应在可能暴露后 72 小时内开始，越早越好。
- [Casual sex emotional outcomes systematic review](https://pubmed.ncbi.nlm.nih.gov/32991206/) 显示休闲性行为后的情绪结果并不单一，酒精、满意度和对伴侣的熟悉程度等因素与结果有关。
- [JMIR：sexual-health app privacy study](https://formative.jmir.org/2020/4/e17901/) 与 [mHealth privacy study](https://mhealth.jmir.org/2018/7/e10211/) 均提示私密外观、提醒方式和情境隐私是性健康产品的重要可用性因素。
- [eSafety Commissioner：Consent](https://www.esafety.gov.au/key-topics/staying-safe/consent) 强调线上性活动也需事先、明确、具体且持续的同意；同意调情或一种线上形式不代表同意其他线上或线下行为，也不得在未经许可时截屏、录制或转发私密内容。

## 开发验收

- 新记录不填写任何感受仍可保存，统计显示“—”而不是默认分。
- 非亲密类型不会残留隐藏的行为、防护或亲密健康字段。
- 选择具体安全套 / 口腔屏障时会同步总状态；改为未记录、未用或无对应行为时，不保留矛盾的屏障细项。
- “清醒放松”与饮酒、疲惫、压力等状态互斥，避免自相矛盾。
- 跟进只有在用户选择类型且未标记完成时进入待跟进列表。
- 有日期的跟进按最近到期排序，无日期事项排在其后。
- 切换对象性别或性取向不应改变可记录的行为结构。
